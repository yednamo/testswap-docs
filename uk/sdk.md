# SDK для Android

SDK через Google Play Integrity підтверджує, що тестувальник встановив застосунок із Google Play за особистим
посиланням TestSwap і щодня відкриває його на справжньому сертифікованому пристрої. Дні тесту відмічаються
автоматично. Підключення необов’язкове.

## Як це працює

1. Тестувальник отримує посилання виду
   `https://play.google.com/store/apps/details?id=<пакет>&referrer=ts_<токен>`.
2. Google Play передає мітку `ts_<токен>` застосунку через Install Referrer: так TestSwap знає, чия це участь.
3. Раз на добу, коли тестувальник відкриває застосунок (запускається Activity), SDK отримує від TestSwap
   одноразовий код (`/sdk/v2/challenge`) і запитує в Google Play токен Integrity з цим кодом (classic-запит).
   Запуск процесу у фоні без відкриття екрана день не відмічає. Доба рахується за часовим поясом, який
   тестувальник обрав на сайті, приєднуючись до тесту, а не за годинником пристрою.
4. SDK надсилає токен на `/sdk/v2/checkin`. TestSwap розшифровує його ключами вашого застосунку й відмічає день,
   лише якщо Google підтвердив усе одразу:
   - запит зроблено для вашого пакета з цим одноразовим кодом, і він свіжий;
   - збірку розпізнано Google Play (`PLAY_RECOGNIZED`);
   - акаунт отримав застосунок із Google Play (`LICENSED`);
   - пристрій сертифікований (`MEETS_DEVICE_INTEGRITY` або `MEETS_STRONG_INTEGRITY`).
5. Після завершення тесту SDK припиняє надсилати запити.

Користувачі, які встановили застосунок не за посиланням TestSwap, нічого не надсилають.

Якщо тестувальник встановив застосунок інакше (пошук у Google Play, сторінка «Стати тестувальником», веб-версія
Google Play), мітки в Install Referrer немає. Тоді на сторінці тесту він натискає «Я встановив застосунок,
зв’язати»: посилання `testswap://<пакет>/link?token=…` відкриває встановлений застосунок, і SDK (0.3+) бере мітку
з нього. Activity для цього оголошує маніфест бібліотеки, у коді застосунку нічого додавати не треба.
Play Integrity перевіряє встановлення так само.

Тест у режимі SDK зараховується, лише якщо застосунок хоч раз пройшов перевірку Play Integrity на пристрої
тестувальника. Дні в режимі SDK відмічає лише SDK: кнопки ручної відмітки на сайті для таких тестів немає.

## Вимоги

- `minSdk` застосунку 26 (Android 8.0) або вище: сховища системних сертифікатів старіших версій не довіряють
  ланцюжку сертифікатів сайту TestSwap, тож SDK не зможе з’єднатися з сервером.
- Застосунок поширюється через Google Play (закрите тестування підходить).
- На пристрої тестувальника є Google Play Store і Google Play services.

## 1. Ключі Play Integrity

TestSwap перевіряє токени вашого застосунку сам, тож йому потрібні ключі відповіді Play Integrity.

1. У Play Console відкрийте розділ Play Integrity API свого застосунку й переконайтеся, що API увімкнено.
2. У налаштуваннях classic-запитів (шифрування відповіді) оберіть власні ключі шифрування замість ключів Google
   і завантажте їх. Покроково: https://developer.android.com/google/play/integrity/classic
3. У кабінеті застосунку в TestSwap вставте **ключ розшифрування** й **ключ перевірки** (обидва в base64) і збережіть.

Поки ключі не додано, застосунок не показується в каталозі й не приймає тестувальників.

Ключ розшифрування зберігається зашифрованим і назад не показується. Якщо ваш власний сервер теж розшифровує
classic-токени Play Integrity, він має перейти на ці самі ключі. Standard-запити це не зачіпає.

## 2. Підключення

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven { url = uri("https://jitpack.io") }
    }
}
```

```kotlin
// app/build.gradle.kts
dependencies {
    implementation("com.github.yednamo:testswap-sdk-android:0.3.0")
}
```

```kotlin
class App : Application() {
    override fun onCreate() {
        super.onCreate()
        TestSwap.init(this, "tsk_...") // ключ із кабінету застосунку в TestSwap
    }
}
```

Не забудьте вказати клас `App` в `AndroidManifest.xml` (`android:name=".App"`). Бібліотека додає дозвіл `INTERNET`.

Версії 0.1.x більше не підтримуються: сервер відповідає на їхні запити кодом 410.

Після завершення тесту SDK нічого не робить: у копій без мітки він мовчить із самого початку, а в тестувальників
зупиняється назавжди, щойно сервер відповідає, що тест завершено. Проте бібліотека лишається в збірці, доки ви
її не приберете: у першому релізі після публікації видаліть залежність і виклик `TestSwap.init`.

## Дані

Надсилаються лише ключ застосунку (публічний, вбудований у збірку), токен участі, токен Google Play Integrity,
версія SDK, а з SDK 0.3 ще модель пристрою з версією Android («Samsung SM-A525F, Android 14») і версія збірки
застосунку («0.6.1 (13)»). TestSwap зберігає результат перевірки (пройдено чи ні й причину відмови), версію SDK,
модель і версії, які розробник бачить у кабінеті біля тестувальника, а для застосунку — текст останньої помилки
перевірки. IP-адреса
клієнта потрапляє лише у звичайні журнали запитів, які ротуються (близько 30 МБ). Ідентифікатори пристрою,
рекламні ідентифікатори чи дані користувача не зберігаються.

Токен Integrity формує Google Play. Опишіть використання Play Integrity API та TestSwap у політиці
конфіденційності й розділі Data safety у Play Console. Якщо застосунок раніше працював без інтернету,
SDK додасть дозвіл `INTERNET`; для таких застосунків простіше обрати режим без SDK.

## Перевірка

1. Розмістіть застосунок у режимі «З SDK», скопіюйте ключ застосунку й додайте ключі Play Integrity.
2. Приєднайтеся до тесту з іншого акаунта, встановіть застосунок за особистим посиланням і відкрийте його.
3. На сторінці тесту має з’явитися «Застосунок підтвердив встановлення через Google Play Integrity»,
   а в кабінеті — час останньої успішної перевірки.
4. Якщо перевірка не пройшла, у кабінеті видно причину останньої відмови (наприклад, ключі від іншого застосунку,
   встановлено не з Google Play, пристрій не пройшов перевірку цілісності).
